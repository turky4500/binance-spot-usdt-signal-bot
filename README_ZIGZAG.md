# نظام ZigZag++ (ساعة) — نظام موازٍ مستقل

بوت موازٍ داخل نفس المستودع: يمسح **كل أزواج Binance Spot/USDT** على **فريم الساعة**
ويطبّق منطق مؤشر **ZigZag++ [LD]** (للمطور DevLucem، المبني على MT4 ZigZag
بإعدادات `Depth=12`, `Deviation=5`, `Backstep=2`)، ثم يرسل إلى تيليجرام:

1. 📥 إشارة دخول (سعر الدخول + الهدف + وقف قاع الشمعة)
2. 🎯 رسالة نجاح — تُرسل **فور لمس** +2% (بلا انتظار إغلاق شمعة)
3. 🛑 رسالة خسارة — عند **إغلاق** شمعة ساعة تحت أدنى سعر لشمعة القاع

**رسائل فردية فقط**: كل عملة تُبلَّغ لوحدها، بلا قوائم جامعة، وبلا حدّ لعدد العملات.
فشل إرسال رسالة واحدة لا يوقف الدورة (`_safe_send`) — تُسجَّل وتُكمل.

وكل رسالة يتبعها سطر **الحكم الشرعي** (بكاش خاص منفصل `data/zigzag/`).

## قواعد النظام

- **القاع**: شمعة 1H مغلقة يكون أدنى سعرها أدنى من كل الشموع الـ11 السابقة —
  أي **أدنى قاع في آخر `Depth=12` شمعة** (بلا نظر للمستقبل).
- **شمعة الدخول**: الشمعة المغلقة التالية مباشرة للقاع.
  - خضراء (إغلاق > افتتاح) وغير دوجي ⇒ **دخول بإغلاقها**.
  - حمراء أو **دوجي** (جسم ≤ 0.05% من السعر) ⇒ **يُلغى القاع** وننتظر قاعًا آخر.
  - إغلاق الشمعة ≤ قاع الإشارة (فجوة سفلية) ⇒ تُرفض الإشارة أيضًا.
- **الهدف**: `سعر الدخول × 1.02` — يُحتسب بمجرد **لمس** أعلى سعر للهدف.
- **الخسارة**: **إغلاق** شمعة ساعة تحت أدنى سعر لشمعة القاع (ليس اللمس).
- **التعارض داخل الشمعة نفسها**: لمس الهدف يسبق إغلاق الخسارة.
- **إشارة واحدة لكل عملة** في وقت واحد؛ بقية العملات بلا حد.
- **رفض الإشارات المتأخرة**: أي إشارة عمرها > ساعتين تُهمَل (حماية بعد توقف البوت).

## الفحص المتكرر (GitHub Actions)

`cron` كل 5 دقائق (أدنى تكرار يدعمه GitHub Actions)، وداخل كل تشغيلة يُعاد جلب
**شموع الدقيقة 1m** لكل إشارة مفتوحة — أي أن دقة كشف لمس الهدف = **دقيقة واحدة**،
وتصل الرسالة خلال 5 دقائق كحد أقصى. عند تعذّر جلب 1m يعمل مسار احتياطي على شموع الساعة.

## متغيّرات البيئة (بها قيم افتراضية صحيحة)

| المتغيّر | الافتراضي | المعنى |
|---|---|---|
| `ZZ_STATE_FILE` | `data/state_zigzag.json` | ملف الحالة المنفصل |
| `ZZ_HALAL_DIR` | `data/zigzag` | كاش الحكم الشرعي المنفصل |
| `ZZ_DEPTH` | `12` | نافذة أدنى قاع (شموع 1H) |
| `ZZ_TARGET_PCT` | `2` | نسبة الهدف من سعر الدخول % (لمس) |
| `ZZ_DOJI_BODY_PCT` | `0.05` | حد الدوجي: جسم ≤ هذه النسبة |
| `ZZ_LOOKBACK_BARS` | `6` | أقصى عمر للقاع عند البحث |
| `ZZ_MAX_ENTRY_AGE_HOURS` | `2` | رفض الإشارات الأقدم من ساعتين |
| `ZZ_MIN_STOP_PCT` | `0` | فلتر اختياري: أدنى مسافة بين الدخول والقاع % (0 = معطّل) |
| `ZZ_COMMISSION_SIDE_PCT` | `0.1` | العمولة لكل جهة % (للدفتر فقط) |

## التشغيل

- **GitHub Actions**: `zigzag-signal-bot-cron.yml` يعمل تلقائيًا كل 5 دقائق (ويقبل التشغيل اليدوي)،
  ويستخدم نفس الأسرار `TELEGRAM_BOT_TOKEN` و`TELEGRAM_CHAT_ID`.
- **محليًا**: `python zigzag_bot.py` (دورة مستمرة) أو `python run_zigzag_once.py` (دورة واحدة).
- **الاختبارات**: `python -m pytest tests/ -q` — تشمل اختبارات عزل تثبت ألّا تُنشأ ملفات الأنظمة الأخرى.

## ملاحظات صادقة

- **الاعتماد الحالي: `Depth=12` بلا فلتر** — قرار المستخدم، مع مراجعة بعد 24 ساعة من
  التشغيل الحقيقي. لتشغيل الفلتر لاحقًا: `ZZ_MIN_STOP_PCT=1.5` في الوركفلو فقط (بلا كود).
- التوقع قريب من الصفر في الاختبار الخلفي، والضجيج عالٍ (375 إشارة/يوم).
  الفلتر يرفع نسبة الفوز ويقلّل الرسائل لكنه يزيد متوسط الخسارة عند الخطأ.
- النسبة المحققة عند اللمس قد تكون أعلى من +2% عند فجوة فوق الهدف (التنفيذ عند الافتتاح).
- أرقام الخلفية اختبارية بتحيّز نجاة (رموز ناجية فقط في القوائم) — للمقارنة النسبية لا كوعد ربح.
- مؤشر ZigZag++ الأصلي يعيد رسم القمم/القيعان (repaint)؛ هنا نعتمد تعريف القاع
  عند **إغلاق شمعته** بلا نظر للمستقبل، فلا إعادة رسم.
