# تجربة تتبّع الاتجاه على كل العملات — فريم 1H

**تاريخ الإعداد:** 2026-11-16 · **الحالة:** الكود جاهز ومُختبر، ويحتاج صلاحية كتابة على المستودع ليُفعَّل.
**القرار:** نظام **تجريبي منفصل وموازٍ** — نظامك الحالي (NW Envelope 1H) **يبقى كما هو بلا أي تعديل**.

---

## 1) ما الذي يعمل بالضبط؟

| البند | القيمة |
|---|---|
| الفريم | **1 ساعة**، تُقيَّم الشمعة **المغلقة** فقط |
| الكون | كل أزواج USDT الفورية المتداولة (`TRADING` + `isSpotTradingAllowed`) عدا 12 عملة مستقرة مربوطة ⇒ **506 زوج** في فحص 2026-11-16 10:50 الرياض |
| الدخول | `close > أعلى high لـ20 شمعة سابقة` **و** `close > EMA(200)` **و** `EMA(200)[j] > EMA(200)[j-10]` |
| الوقف الأولي | `entry − 2.5 × ATR(14)` |
| التتبّع | `trail = max(trail السابق، أدنى low لـ10 شموع سابقة)` — صعود فقط |
| الخروج | `low ≤ trail` ⇒ يُملأ عند `trail` |
| الرسوم | `0.1%` لكل جانب ⇒ `0.2%` تُخصم من النتيجة المعروضة |
| ممنوع | هدف ربح ثابت · إعادة رسم · تعويض هابط · رافعة · شورت · بوابة BTC · مقدّر بديل · مرآة Pine |
| التنفيذ | **لا يوجد**: توصيات/محاكاة فقط، لا أوامر شراء أو بيع |

> تذكير بالتوضيح السابق: `200` = EMA، `20` = قمة Donchian، `14` = ATR لحساب مسافة الوقف فقط،
> `10` = قاع Donchian لخط التتبّع. **ليست** «متوسط 20» ولا «أغلق تحت 14 اخرج».

## 2) الجدولة «نشوف جدوله»

GitHub Actions cron يعمل بـ **UTC**؛ الرياض = UTC+3، فالدقيقة لا تتغير عند التحويل.

| المهمة | الوركفلو | cron (UTC) | بتوقيت الرياض | ما تفعله |
|---|---|---|---|---|
| **دورة التجربة** | `nw-trend-experiment.yml` | `3 * * * *` | **كل ساعة :03** (03:03، 04:03 … 02:03) | يجلب 260 شمعة 1H لكل الأزواج، يقيّم الشمعة المغلقة، يرسل إشارات الدخول/الخروج، يحفظ الحالة |
| **التقرير الختامي** | `nw-trend-daily-report.yml` | `59 20 * * *` | **23:59 كل يوم** | رسالة واحدة فيها إحصائيات اليوم + التراكمي + المراكز المفتوحة، ويحفظ `reports/YYYY-MM-DD.md` |
| نظامك الحالي 1H | `nw-bot.yml` | `5,35 * * * *` | كل :05 و:35 | **لم يتغيّر إطلاقًا** |
| حارس/مراقب 1H | `nw-bot-1h-guard.yml` / `watchdog` | `workflow_run` | — | **لم يتغيّر إطلاقًا** |

- **أول تقرير متوقّع:** ليلة **2026-11-16 23:59** بتوقيت الرياض (يغطي دورات ذلك اليوم).
- **بلا إيقاف تلقائي** (طلبك): التقرير يتكرر كل يوم حتى تطلب الإيقاف. مفاتيح `day_reports` و`sent` تمنع تكرار نفس اليوم/الرسالة.
- إن تأخّر كرون GitHub ساعة أو أكثر، الكود يعالج حتى **6 شموع فائتة** دفعة واحدة بدل تفويتها.

**الإيقاف:** `Disable workflow` للوركفلوتين، أو اضبط متغيّر المستودع `NW_TREND_ENABLED = false`
(بوابة `if` على مستوى المهمة، لا خطوة `exit 0`). للإسكات مع استمرار الحساب: `TELEGRAM_MUTE=1`.

## 3) حجم الرسائل المتوقّع (قياس فعلي)

إعادة محاكاة على **آخر 24 شمعة حقيقية لكل الـ506 أزواج** حتى شمعة `2026-11-16 09:00` الرياض
(الملف `replay_24h.json`):

| المؤشر | القيمة |
|---|---:|
| رسائل كانت ستُرسل | **63 رسالة / 24 ساعة** (37 دخول + 26 خروج) |
| المتوسط | 2.62 رسالة/ساعة |
| أكثر ساعة ازدحامًا | **19 رسالة في شمعة واحدة** |
| زمن الإرسال لأكثر ساعة | ≈ 20 ثانية (فاصل 1.05 ث بين الرسائل + احترام `retry_after` عند 429) |

العميل يستخدم `src/telegram_client.py` المشترك: فاصل أدنى + 3 محاولات + حجب التوكن من السجلات.
لا يوجد حد اصطناعي لعدد الرسائل (اخترت «إشارات فورية كاملة»).

## 4) ⚠️ نتيجة أمانة يجب أن تعرفها قبل التشغيل

نفس إعادة المحاكاة على آخر 24 ساعة **لكل الأزواج** أعطت:

| | |
|---|---:|
| صفقات مغلقة | 26 |
| رابحة / خاسرة | **1 / 25** |
| إجمالي صافي (مجموعي) | **−30.46%** |
| Profit Factor | 0.065 |
| أفضل / أسوأ | +2.10% / −3.38% |

الاستراتيجية التي ربحت `+19.58%` على **HBAR وحده خلال 90 يومًا** خسرت بوضوح على **كل العملات في يوم هابط**.
هذا هو الفرق بين «in-sample على رمز واحد» و«تعميم حي» — وهو بالضبط ما تريد التجربة كشفه.
**لا تعتبرها مربحة، ولا تنفّذ عليها أموالًا حقيقية.** التجربة ترسل توصيات فقط.

  ولا `git push` من المستودع المحلي القديم.
- **489 اختبار ناجح** محليًا: 471 الموجودة + 18 جديدة.
- Supabase كان **مغلقًا** في رسالة الطلب ولم يُستخدم؛ لا حاجة لهذا النظام أصلًا.

## 6) حدود المحاكاة

خروج مُملأ عند `trail` حتى لو فتح السعر دونه (تفاؤل)، بلا انزلاق سعري، بلا دفتر أوامر،
بلا أحداث إدراج/إيقاف تداول، وصفقة واحدة مفتوحة لكل رمز. لا walk-forward ولا رموز متعددة
لفترة أطول من يوم. النتائج **ليست نصيحة استثمارية**.
