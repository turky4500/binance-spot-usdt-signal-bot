# نظام Smart Flow PRO MAX (نسخة معايَرة)

نظام موازٍ رابع مستقل تمامًا في نفس المستودع، يستهدف مؤشر البائع المغلق
**«Smart Flow PRO MAX + Last 2 Signals 🔥»** على TradingView:
مراقبة كل أزواج **Binance Spot / USDT** على **فريم 1H** وإرسال إشارات
**🟢 شراء / 🔴 بيع** إلى تيليجرام (للاطلاع — بلا دورة صفقات).

## لماذا نسخة معايَرة (وليس قراءة مباشرة)؟

- المؤشر كود مغلق عند البائع ولا يوجد منه أي شرح مكتوب.
- المالك (حساب تيليجرام) **غير مشترك في TradingView** → لا يمكن إنشاء أي
  تنبيهات أصلًا على الحساب المجاني → لا طريق لأخذ إشارة نسخة البائع مباشرة.
- الحل: إعادة بناء المنطق في بايثون من لقطات الشارت، ثم **معايرة** المخرجات
  مع لقطات المالك حلقة بعد حلقة حتى التطابق (كل رسالة تحمل سطر
  «نسخة قيد المعايرة» حتى يُثبَت التطابق ويُرفع `SMARTFLOW_CALIBRATION_NOTE=0`).

## فرضية v1.2 (معايَرة من لقطتين على فريم 1H بتاريخ 2026-10-25)

```
انقلاب النافذة (كما يظهر شريط التدفق الأصفر الدرجي على الشارت):
  شراء = إغلاق الشمعة يقطع لأعلى أعلى قمة لعدد BREAK_LEN شموع سابقة
         (والشمعة السابقة لم تكن قد اخترقتها = سلوك ta.crossover)
  بيع  = إغلاق الشمعة يكسر أدنى قاع النافذة نفسها (ta.crossunder)
التبادل الإلزامي (جديد في v1.2 — SMARTFLOW_ALTERNATE=1):
  بعد شراء لا يُقبل إلا بيع (إغلاق الدورة)، وبعد بيع لا يُقبل إلا شراء
  (فتح دورة جديدة) — إشارات مكررة الاتجاه تُهمل مهما مضت من الوقت.
  الدليل: المؤشر ظلّل شراء 10-18 ثم بيع 10-19 وتجاهل 6 بيعات لاحقة وحالته «انتظار»
سعر الدخول المعروض = افتتاح شمعة الانقلاب (طابق لقطة Binance.US: 0.003988 =
  افتتاح شمعة شراء 10-18؛ ولافتة Binance: دخول الشراء = 0.001947 = افتتاحها)
الوقف المبدئي = أدنى قاع النافذة عند الشراء / أعلى قمتها عند البيع
  (دليل إضافي: لافتة صفراء 0.002105 في لقطة Binance = وقف إشارة البيع المحسوب عندنا بالضبط)
الهدفان (هدف 1 /هدف 2) = قاعدتهما من الجدول الجانبي غير معروفة بعد — قيد المعايرة
بوابة RSI (مستوى 45) = معطلة افتراضيًا
```

- سجل المطابقات مع اللقطات (حدثًا بحدث) في `handoff.md` ← قسم «سجل المعايرة».
- **تنبيه بيانات**: لقطة المالك قد تكون على Binance.US أو Binance العالمية؛
  بوت الإنتاج يخدع من Binance العالمية. الرياضيات بين المنصتين تقارب لكن الأسعار
  نفسها قد تتباعد كثيرًا لأزواج قليلة السيولة (مثل ZIL: 0.0028 أمريكا مقابل
  0.0020 العالمية) — عند الحاجة تُختصر بالمعايرة على لقطات Binance العالمية.

- معلمات إعدادات المؤشر الظاهرة (EMA20/EMA50/EMA10/SMA20/RSI14/ATR14) تُحسب
  جميعًا وتُرسَل في الرسائل **للمعايرة فقط** ولا يُشترَط أي منها في الإشارة.
- تفاصيل التقسيم القاع: لقطة الشراء وقعت بتاريخ قاع الانهيار والاتجاه
  (EMA20/EMA50) ما زال هابطًا — لذا تعديل v1.1 أزال شرط الاتجاه الخاص بـ v1.

## الرسائل المرسلة

🟢/🔴 الزوج • الفريم 1H • سعر الإغلاق • مستوى الاختراق/الكسر • وقف مبدئي •
الاتجاه (وصفي) • RSI/SMA/EMA/ATR • وقت الإشارة • الحكم الشرعي (كاش منفصل)

## منطق منع الإزعاج (البوت — ليس من المؤشر الأصلي)

- `SMARTFLOW_SIGNAL_MODE=on_flip` (افتراضي): أول إشارة للرمز أو انقلاب
  الاتجاه فقط.
- `SMARTFLOW_COOLDOWN_BARS=6`: مهلة 6 شموع بين إشارتين متوافقتي الاتجاه.
- كل شمعة مغلقة تُعالَج **مرة واحدة** (`last_processed_open_time` في الحالة)،
  والاستدراك محدود بـ 24 ساعة (أول تشغيل: أحدث شمعة فقط).

## التشغيل

```
python run_smartflow_once.py     # دورة واحدة (كما في GitHub Actions)
python smartflow_bot.py          # تشغيل مستمر محلي
python -m pytest tests/test_smartflow_strategy.py tests/test_smartflow_flow.py -q
```

الوركفلو `.github/workflows/smartflow-signal-bot-cron.yml` يعمل كل 5 دقائق
(في أكثر الدورات طلب واحد فقط لوقت السيرفر — كشف إغلاق شمعة الساعة) ويدفع
الحالة تلقائيًا. لا يحتاج Google Apps Script (يستخدم جدول cron مباشرة).

## متغيرات البيئة

| المتغير | الافتراضي | المعنى |
| --- | --- | --- |
| `SMARTFLOW_STATE_FILE` | `data/state_smartflow.json` | حالة النظام (منفصلة) |
| `SMARTFLOW_HALAL_DIR` | `data/smartflow` | كاش الحكم الشرعي (منفصل) |
| `SMARTFLOW_SIGNALS_LOG` | `data/smartflow/signals_log.csv` | سجل الإشارات |
| `SMARTFLOW_KLINE_LIMIT` | `200` | شموع 1H لكل زوج (RSI/EMA مستقرة بعده) |
| `SMARTFLOW_MAX_CATCHUP_HOURS` | `24` | حد الاستدراك عند التوقف |
| `SMARTFLOW_BREAK_LEN` | `10` | نافذة الانقلاب (اختراق القمة 10) |
| `SMARTFLOW_EMA_LEN / EMA_SLOW_LEN / EMA_FAST_LEN` | `20 / 50 / 10` | للمعايرة والعرض |
| `SMARTFLOW_SMA_LEN` | `20` | للمعايرة والعرض |
| `SMARTFLOW_RSI_LEN` | `14` | للمعايرة والعرض |
| `SMARTFLOW_BUY_RSI_MIN / SELL_RSI_MAX` | `45 / 45` | بوابة RSI (معطلة افتراضيًا) |
| `SMARTFLOW_USE_RSI_GATE` | `0` | تفعيل بوابة RSI |
| `SMARTFLOW_SIGNAL_MODE` | `on_flip` | أو `every_bar` |
| `SMARTFLOW_ALTERNATE` | `1` | v1.2: تبادل إلزامي شراء↔بيع (إهمال المكرر مهما مضى) |
| `SMARTFLOW_COOLDOWN_BARS` | `6` | مهلة (تعمل فقط إذا عُطّل التبادل) |
| `SMARTFLOW_BATCH_LIMIT` | `8` | إشارات أكثر من هذا في شمعة واحدة = رسالة مجمعة (0 = بلا تجميع) |
| `SMARTFLOW_EXCLUDE_NON_CRYPTO` | `1` | عملات رقمية فقط: استثناء الأسهم المرمزة/الذهب/المغلفات المكررة |
| `SMARTFLOW_BUYS_ONLY` | `1` | إرسال الشراء فقط — البيع/كسر الوقف يُسجل في الحالة/السجل بلا رسالة |
| `SMARTFLOW_CALIBRATION_NOTE` | `1` | سطر «نسخة قيد المعايرة» في الرسائل |
| `SMARTFLOW_DRY_RUN` | `0` | طباعة الرسائل في السجل بدل الإرسال (تجارب محلية) |

## المسار الثاني — Webhook (جاهز عند الاشتراك)

مستقبل جاهز في `google_apps_script_webhook.js`: عند اشتراك المالك في
TradingView يُنشأ تنبيه (Alert) على نسخة البائع المغلقة نفسها ويُشاير
مستقبل Google Apps Script المجاني الذي يعيد الإرسال إلى تيليجرام — خطوات
الإعداد داخل رأس الملف نفسه وفي `handoff.md`.
