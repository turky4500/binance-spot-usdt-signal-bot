# Binance Spot USDT Signal Bot — Target Trend

بوت بايثون يراقب جميع أزواج **Binance Spot مقابل USDT** على **فريم 4H** (انتقل من 1H بتاريخ 2026-10-15 — انظر «لماذا 4H» أدناه) ويطبّق مؤشرًا واحدًا معتمدًا، ثم يرسل إلى تيليجرام:

1. 📥 إشارة دخول شراء (مع الأهداف الثلاثة ووقف الخسارة)
2. 🎯 رسالة تحقق أحد الأهداف (تبقى الصفقة مفتوحة)
3. ✅/🛑 رسالة انتهاء الصفقة (رابحة/خاسرة + عدد الأهداف المحققة)

> كل رسالة يتبعها سطر **الحكم الشرعي** للعملة، يُجلب من `cryptohalal.cc`
> مع تخزين مؤقت في `data/halal_verdicts.json`.

## المؤشر المعتمد الوحيد

**Target Trend [BigBeluga]** — محوّل من Pine Script v5 إلى Python في `src/strategy.py`.

المنطق كما في Pine حرفيًا:

```
atr_value = sma(atr(200), 200) * 0.8
sma_high  = sma(high, length) + atr_value      ← خط الاتجاه الصاعد
sma_low   = sma(low,  length) - atr_value      ← خط الاتجاه الهابط (والوقف)

trend = true  عند crossover(close, sma_high)
trend = false عند crossunder(close, sma_low)

signal_up   = انقلاب الاتجاه هابطًا ← صاعدًا → إشارة شراء
signal_down = انقلاب الاتجاه صاعدًا ← هابطًا → إشارة إغلاق الصفقة
```

- `length = 89` (اعتُمد 2026-10-11 بديلًا عن 10 بعد اختبار 4000 شمعة × 30 زوجًا؛ قابل للتغيير بـ `TREND_LENGTH`)
- **فريم العمل: 4H** — انتقل من 1H بتاريخ 2026-10-15 بعد اختبار رجعي عميق (457 يومًا × 30 زوجًا،
  نفس الرموز ونفس الفترة لكلا الفريمين): ‏4H تفوّق في كل مقياس — ‏+336% (بوابة ER0.20+تهدئة96h)
  مقابل ‏+75% لـ1H بالبوابة و**−520%** لـ1H بلاها؛ ونسبة 3/3: ‏19% مقابل 13%، والمتوسط +1.12% مقابل −0.32%.
  ميزة 4H الميكانيكية: وقف أوسع (≈8% مقابل 3.6%) يتحمّل ضجيج الشموع الصغيرة، وإشارة أبطأ تأكيدًا = اختراقات كذبة أقل.
- الأهداف عند الدخول: `الدخول + (5, 10, 15)×ATR` (الفارق من `TREND_TARGET_OFFSET`، افتراضي 0)
- الوقف عند الدخول: قيمة `sma_low` من شمعة الإشارة (ثابت لا يتحرك)
- **الخروج**: إشارة البيع (signal_down) أو لمس وقف الخسارة أو تحقق الأهداف الثلاثة — لا قواعد خروج خارجية
- الأهداف الأول والثاني **رسائل تحقق فقط**؛ تحقق الهدف الثالث يُغلق الصفقة تلقائيًا
  وتُسجل **صفقة ناجحة (win)** مع `exit_reason=all_targets`
- **بوابة الدراسة فوق الإشارة** (2026-10-13؛ أُعيد ضبطها لـ4H 2026-10-15): الإشارة وحدها لا تكفي —
  1) كفاءة الاتجاه `ER(14) < ENTRY_ER_MIN` ⇒ **لا دخول** (سوق متعرج = اختراقات كذبة)،
  2) بعد الوقف تُهمَل إشارات نفس الرمز حتى انتهاء `ENTRY_COOLDOWN_HOURS`.
  المرفوض يُسجَّل في السجل ويبان عدّاده في التقرير اليومي.
  على 4H: `0.20/96h` = ‏+336% مقابل ‏+219% بلا بوابة (رجعي 457 يومًا × 30 زوجًا؛ كل عتبات ER
  من 0.15–0.25 تتفوّق على الأساس — هضبة لا قمة، والنتيجة متسقة مع فحص 100 يوم منفصل).

### الانتباه التقني: `KLINE_LIMIT=499`

`sma(atr(200), 200)` تحتاج ≥ 400 شمعة حتى تصحح، لذلك البوت يجلب **499 شمعة** لكل زوج
(وهو أيضًا أقصى حد يبقى فيه وزن طلب Binance لـ klines = 2 بدل 5). لا تخفض `KLINE_LIMIT`
دون 420 وإلا لن تظهر أي إشارة.

## الرسائل المرسلة

### 1) 📥 الدخول
الزوج • الفريم 4H • سعر الدخول • الهدف 1/2/3 (بنسبتها) • وقف الخسارة (بنسبته) • وقت الإشارة • الحكم الشرعي

### 2) 🎯 تحقق هدف
الزوج • سعر الدخول • سعر الهدف ونسبة الربح • الأهداف المحققة (n من 3) • الوقت والمدة • الحكم الشرعي
— الهدفان الأول والثاني: **الصفقة تبقى مفتوحة** (الإغلاق بإشارة البيع أو الوقف أو تحقق الثلاثة).
— الهدف الثالث: تليه فورًا رسالة الإغلاق كصفقة ناجحة (أنظر 3ب).

### 3) ✅/⚖️/🛑 انتهاء الصفقة
**التصنيف (2026-10-10):**
- 🎉 **ناجحة** (win): تحققت الأهداف الثلاثة — تُغلق تلقائيًا عند الهدف الثالث (أنظر 3ب)
- ⚖️ **تحقّق أهداف فقط** (partial): هدف واحد أو هدفان (1-2 من 3) **أيًا كانت النتيجة الموجبة أو السالبة**
  — لا تُحتسب ضمن الناجحة ولا الخاسرة
- ↗️ **رابحة جزئيًا** (partial_win): **دون تحقق أي هدف** لكن الإغلاق فوق سعر الدخول — لا تُحتسب ضمن الناجحة
- 🛑 **خاسرة** (loss): دون تحقق أي هدف وصافي سالب

وتشمل الرسالة: الدخول والخروج • النتيجة الصافية بعد العمولة • أعلى سعر تحقق •
الأهداف المحققة (n من 3 مع ✔/✖ لكل هدف) • سبب الإغلاق (إشارة بيع / وقف خسارة / تحقق الأهداف الثلاثة) • المدة • الحكم الشرعي

### 3ب) 🎉 انتهاء الصفقة بتحقق الأهداف الثلاثة
تُرسل فور لمس الهدف الثالث: «النتيجة: صفقة ناجحة ✅» • سعر الإغلاق عند الهدف 3 •
النسبة الفعلية والصافية بعد العمولة • كل هدف بنسبته ووقت تحققه • **مدة التحقق**
(من الدخول حتى تحقق الهدف الثالث) • أعلى سعر تحقق • وقت الإغلاق • الحكم الشرعي —
وتُسجَّل في الدفتر `outcome=win` و`exit_reason=all_targets`

### 4) التقارير
- **يومي (00:00)**: عدد الدخول، الأهداف المحققة، الناجحة/الخاسرة/«تحققت أهداف فقط» (⚖️)/«رابحة جزئيًا» (↗️)، نسبة النجاح
- **تحليل يومي**: متوسط النتيجة، أكثر عملة ربحًا/خسارة، توزيع الأهداف، ملاحظات نوعية
- **أسبوعي (الأحد 00:00)**: ملخص الفترة + تحليل الدفتر (المدد، الأهداف، أفضل/أسوأ عملات)

> نسبة النجاح = الناجحة (3 أهداف) ÷ (الناجحة + الخاسرة) — صفقات «تحققت أهداف فقط»
> و«رابحة جزئيًا» لا تدخل أيًا من الطرفين.

## إعدادات Target Trend (متغيرات البيئة)

| المتغير | الافتراضي | المعنى |
|---|---|---|
| `TREND_LENGTH` | `89` | طول الاتجاه (Trend Length) — اعتُمد 89 (2026-10-11) |
| `TREND_TARGET_OFFSET` | `0` | Set Targets في Pine (0 = أهداف 5/10/15×ATR) |
| `ENTRY_ER_MIN` | `0.20` | بوابة الدراسة: أقل كفاءة اتجاه (Kaufman ER) مقبولة للدخول — `0` = تعطيل |
| `ENTRY_ER_LEN` | `14` | فترة حساب كفاءة الاتجاه |
| `ENTRY_COOLDOWN_HOURS` | `96` | تهدئة إشارات الرمز بعد الوقف — `0` = تعطيل |
| `BINANCE_INTERVAL` | `4h` | فريم العمل (`1h` أو `4h`) — كشف الشمعة المغلقة واعٍ بالفريم |
| `KLINE_LIMIT` | `499` | عدد شموع الفريم لكل زوج (لا تقللها دون `min_bars + 1` = 411) |
| `EXCLUDE_PEGGED_STABLES` | `1` | استثناء أزواج العملات المستقرة المربوطة |

## تشغيله عبر GitHub Actions + Google Apps Script
الـ Workflow جاهز في `/.github/workflows/signal-bot-cron.yml` ويعمل عبر `workflow_dispatch`
فقط، ويُستدعى كل 5 دقائق من **Google Apps Script** باستخدام `google_apps_script_trigger.js`.

### ماذا يفعل؟
- يشغّل البوت **مرة واحدة كل 5 دقائق**
- يفحص **تحقق الأهداف والوقف داخل الساعة** باستخدام شموع 1 دقيقة
- يفحص **إشارة الدخول وإشارة البيع** عند إغلاق شمعة الساعة
- يحفظ الحالة في `data/state.json` ويعمل commit تلقائيًا عند التغيّر

### الأسرار المطلوبة في GitHub
- `TELEGRAM_BOT_TOKEN`
- `TELEGRAM_CHAT_ID`

### إعداد Google Apps Script
1. افتح `script.google.com` وأنشئ مشروعًا جديدًا
2. الصق محتوى `google_apps_script_trigger.js`
3. من **Project Settings > Script properties** أضف:
   - `GITHUB_TOKEN`
   - `GITHUB_OWNER=turky4500`
   - `GITHUB_REPO=binance-spot-usdt-signal-bot`
   - `GITHUB_WORKFLOW=signal-bot-cron.yml`
   - `GITHUB_REF=main`
4. شغّل الدالة `createFiveMinuteTrigger` مرة واحدة ووافق على الصلاحيات

> السكربت يتحقق أولًا هل يوجد Workflow ما زال يعمل، وإذا وجد تشغيلًا نشطًا
> فإنه **لن يرسل Dispatch جديدًا** — هذا يمنع تكرار الرسائل.
